# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

There is no build, lint or test tooling, and no dependencies. To run the app, open `index.html` in a recent browser (it uses nested CSS).

## Architecture

The markup is in `index.html`, the styles in `styles.css`, and all the JavaScript in `script.js`, a plain script (not a module) loaded at the end of `<body>`. The page has three screens, `#home`, `#game` and `#results`, switched with `showScreen` (the `hidden` attribute). The home screen offers 1, 2 or 3 darts a turn. Each opens the `#options` `<dialog>` (singles, doubles, triples, number of turns, throw animation, shadows), and OK starts a game. `saveOptions` stores each mode's last options in localStorage (`darts-options-1` to `-3`) and `loadOptions` fills the dialog from them; the form's initial HTML state is the default. The player types the turn's total. The home screen also offers 301 and 501, scored on a real board. Both buttons (`data-start`) share the `#match-options` dialog (players, double out), saved per starting score under `darts-options-301` and `darts-options-501`.

- **Game state:** `game` holds the game in progress, or `null` outside a game. In the drill the number pad and keyboard only respond while `game.waiting` is true (see `padReady`), which `checkAnswer` clears while it shows the result before the next turn. `game.darts` holds the current turn's darts.
- **Throwing:** `buildTargets` lists the beds allowed by the options (25 counts as a single, bull as a double). `randomPointIn` picks a point in millimetres within the central `LANDING_SPREAD` of a bed, with the marker (`DART_RADIUS`) kept clear of the radial wires and the centre at least `WIRE_MARGIN` from any wire, so `scoreAt` at that point always agrees with the target. `randomPointAwayFrom` retries to keep darts in a turn `DART_SPACING` apart. `drawDartboard` draws the turn's darts last.
- **Throw animation:** `throwTurn` gives each dart a `thrownAt` time, a `flight` time (`THROW_DURATION`, or 0 with the animation toggled off) and a `shadow` flag, spacing darts `flight + THROW_PAUSE` apart. It runs `animateTurn` on `requestAnimationFrame` until the last dart has landed and its impact ring faded. `drawDart` works out each dart's flight from the current time, so a resize mid-throw just redraws the same frame. `game.waiting` turns on when the last dart lands, and `setPadEnabled` greys out the keypad until then. The dialog's Display toggles (`animation`, `shadows`) are saved with the other options. Shadows is disabled while the animation is off, and the animation defaults to off under `prefers-reduced-motion`.
- **301 and 501:** `match` holds a 301 or 501 game in progress (`match.start` is the starting score), or `null`; only one of `game` and `match` is set. It uses the game screen with `#scoreboard` in place of `#board` (`showGameScreen`). `match.visits` is the only state: remaining scores, averages and whose turn it is are all derived from it, so `undoVisit` just pops. `VISIT_SCORES` (totals three darts can make) validates entries and `DOUBLE_FINISHES` decides whether reaching 0 with double out is a checkout or a bust. When a player's remaining score can be finished in one visit, `checkout` gives the darts to throw, shown as a list down the left of their card: with double out from the `DOUBLE_OUT_CHECKOUTS` chart, otherwise the fewest darts, highest first (`finishIn`). Clicking a name on the scoreboard swaps it for a text field (`editName`); names are saved under `darts-player-names`, shared by both games. `replay` restarts whichever game was played last.
- **Units:** all radii in `dartboard` are millimetres from the board centre. Convert with `px(mm)` when drawing. `scoreAt` divides by `dartboard.scale` instead, so drawing and hit detection always agree.
- **Segments:** `SEGMENT_NUMBERS` lists the numbers clockwise from the top. Segment `i` is centred on `-90° + i * 18°` in canvas angles (clockwise, since y points down). Even indexes have black singles with red rings, odd ones cream singles with green rings.
- **Draw order:** `drawDartboard` paints in layers, so the order of its calls matters. Wires are drawn over the segments and bulls, then numbers, then the darts.
- **Scaling:** the page is one screen tall. The number pad takes the height it needs, and the canvas fills the rest of the width and height. `resizeCanvas` runs from a `ResizeObserver`. It matches the canvas resolution to its displayed size (times `devicePixelRatio`), centres the board and sets `dartboard.scale` so the board fits the shorter side. Drawing and `scoreAt` both use CSS pixels, so mouse `offsetX`/`offsetY` can be passed straight in. The number pad is a CSS grid sized with `clamp()` so it stays large on phones.
